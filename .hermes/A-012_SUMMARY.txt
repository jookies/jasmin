KEY FINDINGS:

1. TOPOLOGY REDECLARATION: ✅ YES, ON EVERY RECONNECT
   ─────────────────────────────────────────────────
   • Exchanges redeclared: YES (by each consuming component)
   • Queues redeclared: YES (via named_queue_declare wrapper)
   • Bindings redeclared: YES (via queue_bind)
   • Timing: Immediately after channelReady deferred fires
   
   Mechanism:
   - Factory resets channelReady deferred on reconnect
   - Each component (Router, Throwers, Managers) waits on channelReady
   - Upon firing, component redeclares all topology
   - AMQP operations are idempotent (same params = no error)


2. CONSUMER RECOVERY: ❌ NO AUTOMATIC RECOVERY
   ──────────────────────────────────────────
   • Consumers automatically restored: NO
   • Consumer setup: Called once in addAmqpBroker() at startup
   • Recovery behavior: Consumers NOT re-established on reconnect
   • Impact: Consumers can be stranded after reconnection
   
   Design Gap:
   - No mechanism re-calls subscribe/addAmqpBroker on reconnect
   - Application must detect reconnect and manually restore consumers
   - No error handling observed for lost consumers


3. IN-FLIGHT MESSAGE HANDLING: ⚠️ PARTIAL (TOPOLOGY YES, CONSUMER NO)
   ──────────────────────────────────────────────────────────────
   • Unack'd message retention: YES (held in queue by broker)
   • Redelivery on reconnect: CONDITIONAL
     - Topology redeclared: YES ✅
     - Consumer re-established: NO ❌
     - Net effect: Message stays in queue but undelivered (stranded)
   
   Acknowledgment Model:
   - All consumers use no_ack=False (manual ACK required)
   - Messages can be explicitly rejected/requeued with basic_reject()
   - Connection loss = no ACK sent = message retained by broker

IMPLICATIONS FOR GO REWRITE:

Do replicate:
  ✅ Topology redeclaration on every reconnect
  ✅ Idempotent exchange/queue/binding declarations
  ✅ Channel readiness signaling (like channelReady)
  ✅ Configurable reconnect delays
  ✅ Unack'd message retention

Do NOT replicate (gaps in legacy):
  ❌ Lack of automatic consumer recovery
  ❌ Consumers being stranded on reconnect
  ❌ Heartbeat disabled by default

Improvements for Go version:
  • Implement automatic consumer re-establishment on reconnect
  • Track in-flight messages explicitly for recovery
  • Enable heartbeat by default for faster connection failure detection
  • Implement automatic re-subscription callbacks on reconnect
