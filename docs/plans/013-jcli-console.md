## Context

jCli is Jasmin's canonical management surface and the one operators have scripted against. `JCLI_MATRIX.md` freezes 18 contract rows (J-001…J-018) at transcript strictness: "prompt bytes, line ordering, spacing where scripts may parse output, success/error text and effective control-plane mutation."

The legacy implementation is a Twisted `recvline.HistoricRecvLine` terminal application (`jasmin/protocols/cli/protocol.py`) with per-entity managers (`usersm`, `groupsm`, `filtersm`, `morouterm`, `mtrouterm`, `mtinterceptorm`, `mointerceptorm`, `smppccm`, `httpccm`, `statsm`) and an interactive key/value session mode driven by an `@Session` decorator (`managers.py:1-60`).

The known strings that must match exactly include the banner `Welcome to Jasmin <release> console\nType help or ? to list commands.\n`, the prompt `jcli : `, and the auth sequence `Authentication required.\n\n` → `Username: ` → `Password: ` (`jasmin/protocols/cli/jcli.py:20-146`).

**This plan depends on plan 012.** jCli manages nine entity types; the Go admin core covers three until 012 lands the rest. jCli commands must call those services — never reimplement business logic — so that all three faces stay consistent by construction.

## Approach

A plain `net`-based line server (no terminal emulation library), because the contract we owe is the *transcript*, not full readline behavior. Structure mirrors the legacy layout:

- `session.go` — connection lifecycle, banner, auth, prompt, quit, timeout.
- `dispatch.go` — command table, `help`/`?`, unknown-command text.
- `manager.go` — shared list/add/update/remove/show/flush verbs and the interactive key/value session state machine.
- `managers_*.go` — one file per entity, mapping fields to the admin service calls.
- `render.go` — table formatting helpers, kept in one place because column spacing is contract.

Line editing and history are explicitly out of scope for v1 (see Risks): scripted clients send whole lines, and the matrix's strictness is about emitted bytes. Tab completion (J-002) is handled at the command-name level only.

**Transcript tests are the deliverable, not an afterthought.** Every command gets a golden transcript test: feed a scripted byte stream, compare emitted bytes to a fixture captured from the Python oracle. Fixtures are generated by a harness script against the frozen baseline rather than hand-written, so "we think this matches" never enters the process.

## Steps

### Step 1: Transcript-capture harness

- **Files:** new `scripts/compat/capture_jcli_transcript.py`, `spec/compatibility/fixtures/jcli/README.md`.
- **Changes:** Drive the frozen Python jCli over a socket with a scripted list of input lines, recording the exact byte stream returned. Emit one fixture file per scenario (`<id>.jsonl`: input lines + expected output bytes, base64-encoded to survive control characters). Deterministic ordering; no timestamps in fixtures.
- **Verify:** Capture J-001 (connect, auth success, auth failure, quit) and confirm re-running produces byte-identical fixtures. Any nondeterminism (release string, timing) is normalised explicitly and documented in the README.

### Step 2: Session, auth, banner, prompt, quit (J-001, J-002) — DONE

- **Files:** new `internal/app/jcli/{server,session,dispatch,render}.go` + tests; `internal/app/gateway/config.go` (`jcli` config block: `listen_address`, `username`, `password` secret-ref, `idle_timeout`); `internal/app/gateway/runtime.go` (construct + expose); `cmd/jasmin-go-httpapi/main.go` (third listener, same shutdown context as the admin UI).
- **Changes:** Accept a connection, write the banner, run the auth exchange, then loop on lines dispatching to commands. Implement `quit`, `help`, `?`, and the unknown-command message. Idle timeout closes the session. Credentials compare constant-time; the password is a secret-ref like every other credential.
- **Verify:** `go test ./internal/app/jcli/ -run Session` against the Step 1 fixtures — byte-exact banner, prompts, auth-failure text, and `quit`. Manual: `telnet 127.0.0.1 8990`.

- **Verify:** Transcript tests per entity against fixtures captured from an oracle seeded with identical state. A diff in a single space fails the test — that is the point.

### Step 4: Mutating verbs and interactive sessions (J-018, plus add/update/remove for the above)

- **Files:** `internal/app/jcli/session_interactive.go`, the `managers_*.go` files, tests.
- **Changes:** Implement the `@Session`-equivalent state machine: `add`/`update` enter key/value prompt mode, collecting fields until `ok` (save) or `ko` (abort), validating keys and values per entity, then calling the admin service. Field names and error text come from the oracle. `remove` and `flush` are single-shot with confirmation text.
- **Verify:** Transcript tests for the full add flow including invalid key, invalid value, abort, and save; after each, assert the **effective mutation** through the admin service (the matrix requires both transcript and control-plane effect).

### Step 5: Remaining managers (J-003, J-005, J-006, J-007, J-010, J-011)

- **Files:** `managers_group.go`, `managers_filter.go`, `managers_mtinterceptor.go`, `managers_mointerceptor.go`; user credential/quota fields; user SMPP unbind/ban.
- **Changes:** Depends on plan 012 Steps 3–6 landing the group, interceptor and filter services. User credentials (J-005) is the largest single surface — every HTTP/SMPP authorization, filter, default and quota field.
- **Verify:** Transcript tests per manager; J-005 needs a field-by-field table test rather than a few happy paths.

### Step 6: `stats` (J-014)

- **Files:** `managers_stats.go`, tests.
- **Changes:** Render users/user, SMPPc(s), SMPPs and HTTP stats with exact names and formatting, sourced from the same counters `/metrics` exposes.
- **Verify:** Transcript tests; cross-check that a counter shown by `stats` matches the `/metrics` value for the same underlying metric.

### Step 7: `persist` / `load` / autoload (J-015, J-016, J-017)

- **Files:** `managers_persist.go`, `docs/adr/00X-jcli-persistence.md`.
- **Changes:** **Decision required before coding.** The Go admin core persists every mutation to SQLite immediately (apply-first-then-persist), so `persist`/`load` have no semantic role. Two options: (a) implement them as accepted no-ops returning the oracle's success text, keeping scripts that call `persist` working; (b) declare them a deviation. Recommendation: **(a)** — a script ending in `persist` must not break, and the success text is cheap to emit truthfully since the state genuinely is durable. `load` with an explicit profile has no equivalent and should return a clear error rather than silently doing nothing. Autoload (J-017, `jcli-prod` startup) maps to `LoadAndApply` at boot, which already exists.
- **Verify:** Transcript tests for `persist`; an explicit error transcript for unsupported `load` profiles, recorded in `DEVIATIONS.md`.

### Step 8: Matrix reconciliation

- **Files:** `spec/compatibility/JCLI_MATRIX.md`, `spec/compatibility/DEVIATIONS.md`, `docs/STATUS.md`.
- **Changes:** Move each row from `INVENTORIED` to `MATCH` only when its transcript tests pass against oracle-captured fixtures. Record every deviation with its reason.
- **Verify:** No row claims `MATCH` without a passing fixture-backed test — this is the first surface in the project to earn that status, so the bar it sets matters.

## End-to-end verification

Run the Go gateway and the frozen Python stack side by side, seeded identically. Drive the **same scripted session** (a realistic provisioning run: add group, add user, add connector, add MT route, add MO route, list everything, persist, quit) against both consoles and diff the byte streams. Zero diff is the pass condition. Then confirm the mutations are visible through the other two faces — `/admin` JSON and the web UI — proving all three share one core.

## Rollback

The console is inert unless `jcli.listen_address` is set: no listener, no new routes, no behavior change. Each step is additive and independently revertible.

## Risks

- **Transcript strictness is unforgiving.** A space or newline diff is a failure. Mitigated by capturing fixtures from the oracle rather than authoring them, and by doing the renderer first (Step 3) where mutation risk is zero.
- **Terminal behavior out of scope.** Legacy jCli is a full `HistoricRecvLine` terminal: arrow-key history, in-line editing, tab completion. v1 serves scripted and simple interactive clients. An operator with muscle memory for arrow-key history will notice. This must be stated in the matrix as a scoped deviation rather than discovered in production.
- **Ordering dependency on plan 012.** Steps 5 partially blocks on 012's services. Sequence 012 Steps 1–6 before jCli Step 5, or the commands have nothing to call.
- **Two surfaces, one core, divergent validation.** If a command validates differently from the equivalent API handler, the faces drift. Mitigated by keeping *all* validation in the admin services and letting both faces surface the same sentinel errors.
- **A telnet management port is unauthenticated network surface until the auth exchange completes.** Bind internal-only, exactly as documented for the web UI listener, and support a secret-ref password.
