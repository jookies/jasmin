# Known legacy quirks

Baseline: `0aac58e466d583d0f0436df7b8afa3dc96191263`.

These behaviors must not be silently corrected during parity.

| ID | Quirk | Source/evidence | Compatibility rule |
|---|---|---|---|
| Q-001 | `RandomRoundrobin*Route` uses random choice, not deterministic round-robin. | `jasmin/routing/Routes.py` | Preserve in legacy route type; add corrected strategy under a new type later. |
| Q-002 | Default route occupies order `0`; higher route order is evaluated first and same-order add replaces. | `RoutingTables.py`, routing tests | Reproduce decision order exactly. |
| Q-003 | `BestQualityMTRoute` is an unimplemented/skipped stub. | route source/tests | Do not count it as working parity. |
| Q-004 | Package metadata says `0.12`, runtime constants report `0.11.1`. | `pyproject.toml`, `jasmin/__init__.py` | Compatibility identity is commit SHA plus fixtures. |
| Q-005 | Successful MO/DLR HTTP callback requires status 200 and exact body `ACK/Jasmin`. | `routing/throwers.py` | Preserve exact ACK and retry behavior. |
| Q-006 | DLR SMSC IDs are uppercased, leading zeros stripped and may use configured decimal/hex conversion. | `managers/content.py`, `listeners.py` | Preserve mapping and missing/expired-key behavior. |
| Q-007 | MO multipart state uses `longDeliverSm:<cid>:<ref>:<destination>` with fixed TTL 300 seconds. | `managers/listeners.py` | Preserve key/TTL in compat adapter. |
| Q-008 | Route prices and balances use Python float. | `routing/Bills.py`, route tests | Fixed-point is allowed only after a differential rounding corpus proves identical decisions/output. |
| Q-009 | Profiles and many PB/AMQP bodies use Python pickle. | router/managers/content | Only trusted Python bridge may decode; Go never does. |
| Q-010 | Startup can continue after some component failures. | `jasmin/bin/jasmind.py` | Record exact readiness behavior; secure mode may fail fast as a documented mode difference. |
| Q-011 | Stats are process-local and reset on restart. | stats modules/docs | Preserve legacy metrics while adding separate durable telemetry. |
| Q-012 | GET `/send` remains supported for backward compatibility. | HTTP send endpoint | Do not remove during parity. |
| Q-013 | Unlimited balance/count can be represented as `None` internally and `ND` in API output. | credentials/HTTP tests | Preserve type and formatting at edges. |
| Q-014 | Billing may split charge between enqueue and successful `submit_sm_resp`. | router/listeners | Differential tests must cover redelivery and exactly-once delta. |
| Q-015 | A captured `deliver_sm` with `message_payload` decodes, but the Python encoder rejects the decoded payload on re-encode with a size mismatch. | `compat/fixtures/smpp/baseline.json` case `deliver_sm_dlr_message_payload`; `tests/protocols/smpp/test_pdu_decoding.py` | Preserve the captured decode-success/re-encode-failure boundary until a deviation is approved. |
| Q-016 | The Python decoder accepts captured unknown vendor TLV `0x1403`, but re-encoding silently omits it. | `compat/fixtures/smpp/baseline.json` case `submit_sm_unknown_vendor_tlv` | Accept and drop this unknown TLV in compatibility mode; do not claim vendor-TLV fidelity. |
| Q-017 | A normalized custom-TLV 4-tuple whose type field is falsy but non-null (`''`, `0`, `false`) bypasses type resolution, is validated against the connector rule's type, yet encodes via the octet fallback — validation and encoding disagree. | `jasmin/tools/tlv_encoder.py` (`resolve_tlv_types` checks `t[2] is not None`; `encode_tlv_value` does `(tlv_type or '').strip()`); probe evidence: `[(5121, None, '', '7')]` resolves unchanged and encodes `1401000137` while a `None` type resolves to `Int8` and encodes `140100080000000000000007` | Go `tlv.Normalize` maps falsy non-null type fields to unresolved `""` so the rule's type applies consistently end to end — resolve, validate, and wire (on the actual wire the legacy disagreement deepens: the patched `encodeRawParams` matches type names exactly, so these falsy-typed tuples are validated and then silently absent from the emitted PDU); exclude these shapes from any future normalize oracle corpus or capture them as documented deviations. |
| Q-018 | The legacy submit wire path (`smpp.pdu3` `encodeRawParams` + the fork's Int8 patch) disagrees with the validation encoder (`encode_tlv_value`): type names match exactly and untrimmed (`' Int8 '`, `'Foo'`, `''` are silently skipped after validation measured them); Int8 entries are split out and emitted after all other entries; tags are not masked (out-of-uint16 raises where `encode_custom_tlvs` masks); Int1/2/4 crash on string/float values that validation coerced; octet types crash on integer values that validation rendered via `str()`; a non-null length hint is honored verbatim — padding-crashes when larger than the encoded value and emits a corrupt length field when smaller. | `smpp.pdu3` `pdu_encoding.py` `encodeRawParams`; `jasmin/tools/tlv_encoder.py` `install_pdu_encoder_patch`; probe-derived expectations in `internal/core/tlv/wire_test.go`; byte-parity evidence in `internal/core/smppc/vendor_tlv_differential_test.go` | Go `tlv.WireEncodeCustomTLVs` mirrors every valid-frame emission byte-for-byte (including the Int8 reorder and exact type-name skips) and maps the legacy crash paths to message rejection (the listener's `rejectMessage` outcome); the two corrupt-frame emissions (length hint smaller than the body, Int8 hint ≠ 8) are consciously rejected instead of reproduced. The AMQP submit projection now preserves `pdu.custom_tlvs` tuples for this pipeline; Q-016's accept-and-drop stays true for TLVs decoded off actual wire bytes. |
