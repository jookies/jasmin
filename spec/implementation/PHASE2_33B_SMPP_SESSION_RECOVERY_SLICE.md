# Phase 2.33B — SMPP Session Recovery and Control-PDU Fidelity

## Goal

Repair the audited gap between the Phase 2.33 fixture-level session API and a live connector-owned SMPP session before starting Phase 2.34 pacing integration. The bounded result must have one connection reader, valid bind/enquire-link control PDUs, deterministic connection ownership, and exactly-once settlement of pending AMQP deliveries on response, timeout, write failure, cancellation, or connection loss.

## Selection evidence

- `PHASE2_33A_OUTBOUND_PRODUCTION_WIRING_SLICE.md` explicitly leaves Phase 2.33 timer/correlation defects unfinished.
- `internal/core/smppc/connector.go` currently waits in a competing one-byte `conn.Read`, defers `conn.Close`, and only starts `Session.Run` after `connectAndBind` returns; the session therefore cannot own a live connection.
- `internal/transport/smppwire/codec.go` does not encode/decode `bind_transceiver_resp`, `enquire_link`, or `enquire_link_resp`; Phase 2.33's keep-alive writer currently discards the resulting unsupported-command error.
- `PHASE2_33_SMPP_CONNECTOR_SESSION_SLICE.md` names SC-004 pacing as Phase 2.34. Pacing remains the next slice, but production pacing cannot be integrated safely until session ownership and settlement are real.

## Scope

### Oracle/test harness

- Extend the existing frozen-Python SMPP wire capture with `bind_transceiver_resp`, `enquire_link`, and `enquire_link_resp` cases generated by the legacy `smpp` encoder.
- Update the coupled schema, trusted fixture registry/fingerprints, coverage rows, and generic no-skip Go differential harness.
- Add RED lifecycle tests proving a single reader, bind-response gating, valid enquire-link bytes, response correlation, timeout/connection-loss/cancellation settlement, write-error cleanup, and reconnect.

### Production implementation

- Add typed SMPP control-PDU codec support for the captured cases.
- Make the connector transfer ownership of the socket to exactly one running `Session`; remove the competing one-byte reader and the premature deferred close.
- Require a successful, sequence-matched `bind_transceiver_resp` before `BOUND` and AMQP consumption.
- Serialize all socket writes so submit and keep-alive frames cannot interleave.
- Make session shutdown idempotent and ensure each pending delivery is removed before one terminal settlement attempt.
- Propagate session termination to the connector loop, cancel the consumer, clear the published session, and reconnect according to the existing bounded policy.

### Documentation

- Keep `S-005`, `SP-002`, `SP-005`, `SC-003`, `SC-005`, and `SC-006` at `GO-PARTIAL`; update notes only for the newly proven subset.
- Keep `SC-004` at `GO-PARTIAL`; Phase 2.34 remains pacing integration.
- Recount all authoritative compatibility matrices before stable candidate identity.

## Non-goals

- Integrating `Pacer` into the AMQP consumer (Phase 2.34).
- Full connector configuration/lifecycle/failover parity (`SC-001`, `SC-002`, `SC-007`).
- TLS, graceful unbind, bind RX/TX modes, arbitrary bind status mapping, or complete reconnect statistics.
- Decoding the protocol-2 AMQP `SubmitSM` body into every SMPP field; semantic serializer fidelity remains a separate explicit boundary and must not be promoted by this slice.
- DLR/MO processing, multipart publication, deployment manifests, or starting a connector process from the HTTP executable.

## Acceptance criteria

1. Frozen Python capture produces byte-exact bind response and enquire-link request/response fixtures; two aggregate regenerations are identical and committed fixtures have zero diff.
2. The generic Go SMPP differential harness executes every fixture without skips; control PDUs round-trip to exact legacy bytes.
3. A simulated SMSC proves: bind request → successful matching bind response → `BOUND` → AMQP consume → submit request → correlated response settlement.
4. No goroutine other than `Session.Run` reads the established socket. An unexpected/failed/mismatched bind response prevents `BOUND` and consumer startup.
5. Submit, enquire-link, and response writes are serialized. Encode/write errors are surfaced and leave no pending timer capable of a second settlement.
6. Context cancellation, response timeout, and connection loss each requeue every pending delivery once, terminate the session, and unblock connector stop/reconnect.
7. Focused tests pass 20 times, followed by full Go, race, vet, build, applicable fuzz, Python verifier/schema/unit, frozen manifest, secret scan, and clean-workspace gates.
8. A stable candidate receives final Ralph code audit with no unresolved high-severity finding.
9. Plan plus implementation are committed and pushed together; the exact SHA passes GitHub Actions 4/4, local/remote SHA match, the workspace is clean, and the final orchestrator emits the LoopKey.
